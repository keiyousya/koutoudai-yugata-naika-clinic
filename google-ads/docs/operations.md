## 1. キャンペーン構成

平日と土日で2本に分けている。

| キャンペーン | 配信曜日 | 日予算 | 上限CPC |
|---|---|---|---|
| 検索_内科_土日 | 土・日 | 3,000円 | 200円 |
| 検索_内科_平日（月水木金） | 月・水・木・金 | 3,000円 | 100円 |

両方とも **TARGET_SPEND（クリック数の最大化）**、検索＋検索パートナー＋ディスプレイ拡張ON、クリニックを中心とした半径4km、日本語。命名規則は `検索_<商材>_<配信ターゲット>`。

**なぜ分割したか:** Google広告に「曜日別の日予算」という設定は存在しない。「予算スケジュール」は特定の日付範囲用で曜日の繰り返し指定はできず、入札調整では予算上限を動かせない。キャンペーンを分けるのが唯一の手段だった（2026-08-09実施）。

**配信スケジュール:**

- 平日: 12:00-13:00（×1.20） / 13:00-14:00 / 16:00-17:00 / 17:00-18:00（×1.25） / 18:00-20:30
- 土日: 12:00-17:00 / 17:00-20:30（いずれも等倍）

診療時間は月水木金 17:00-21:00、土日 14:00-21:00、火・祝は休診、最終受付20:45。**診療時間より早い12時台から配信しているのは意図的**で、社会人が昼休憩に探して夜の受診を決める「先取り検索」を取るため。

**上限CPCが平日だけ100円な理由:** 2026-08-10の学習期間トラブル（後述）で引き下げた。土日の200円は2026-06のキャンペーン作成時から見直されていない継承値で、根拠はない。ただし土日の実績CPCは42〜70円で200円に届いておらず実害もないため、触っていない（入札設定の変更は学習期間を誘発するので、理由なく動かさない）。

## 2. 実証済みの知見

### やっても効果がなかったこと

**❌ 日予算の増額**

2回検証して2回とも予約が増えなかった。

| 検証 | 投下 | 結果 |
|---|---|---|
| 2026-08-08 | クリック +82% | 予約 **±0件** |
| 2026-08-10 | 費用3.4倍・クリック2.5倍・表示シェア10%→26% | 予約 **+2件**（増分1件あたり約1,930円） |

平日の予約1件あたり広告費の平常値は121〜183円なので、増分1,930円は桁が違う。**集患を増やしたいときに予算を積むのは費用対効果が悪い。**

**❌ 配信半径の拡大**

平日の表示シェアは約10%で、失っている理由の内訳は**ランク不足が77〜90%、予算不足は0〜14%**。半径4km圏内にすでに9割の表示機会が余っている状態なので、範囲を広げても勝てない入札が増えて予算が薄く散るだけ。

（土日は逆に予算不足が主因で63〜78%。曜日で構造が違う）

### 効果があったこと

**✅ 上限CPCの引き下げ**

2026-08-10、上限CPCを200円→100円にしたところ、同日中に以下が改善した。

| 区間 | CPC | CTR |
|---|---|---|
| 12-13時（上限200円） | 137円 | 3.9% |
| 16-20時（上限100円） | **77円** | **10.7%** |

**高く買っていた枠は質の悪い枠だった。** 上限を半分にしてCPCが半減し、CTRは2.7倍になった。

### その他の確定事項

- **入札調整（ad_schedule の bid_modifier）は TARGET_SPEND でも効く。** 12時台（×1.20）のクリック実費が240円＝上限CPC 200円×1.20ちょうどで頭打ちになることを確認済み。公式ドキュメント間で記述が矛盾しているが、実測では効いている
- **平日は1日の予約の半分以上が16時以降に作られる。** 日中に「今日は予約が少ない」と感じても、その時点ではまだ半分も終わっていない。比べるなら「16時までの累計」を前週の同条件と並べる（平日の16時まで累計は4〜6件が平常値）
- **朝9-11時は広告なしでも予約が発生する**（土1.40件/日、日1.25件/日）。12時ですら成績が悪いため、配信開始の前倒しは見送っている

## 3. 品質スコアの現状

伸びしろは予算ではなく広告ランクにある。キーワード別の品質スコアに傾向がはっきり出ている。

| キーワード | 品質スコア | 広告の関連性 | LPの利便性 | 推定CTR |
|---|---|---|---|---|
| 内科 夜 | **8** | 平均以上 | 平均 | 平均以上 |
| 日曜日 やってる内科 仙台 | **7** | 平均 | 平均 | 平均以上 |
| 病院 内科 | 2 | 平均 | 平均以下 | 平均以下 |
| 病院 近く | **1** | 平均以下 | 平均以下 | 平均以下 |
| 日曜 病院 | **1** | 平均以下 | 平均以下 | 平均以下 |

**「夜」「日曜にやってる」という自院の強みを含む語だけが評価されている。** 汎用的な「病院」「近く」は軒並み低い。

そして**LPの利便性が「平均より上」のキーワードは1つもない**。全キーワードをトップページに送っているのが全体の足かせになっている。

さらに、最も広告費を使っているキーワード（表示1,824回・ある日の予算の38%）は**品質スコアが未評価**の状態。

### マッチタイプ

**ポジティブキーワード25語はすべて部分一致（BROAD）。** 2026-08-10の平日は検索語句240種・表示649回のうち、**0クリックだった語句が210種・411回＝63%**を占めた。中身は競合医療機関名と診療科違いが大半。

部分一致はコンバージョン信号を伴うスマート入札とセットで機能する仕組みなので、CV計測が整うまではフレーズ/完全一致への変更を判断しない。

### 除外キーワード

競合医療機関名は**共有の除外キーワードリスト「競合医療機関名」（フレーズ一致）** に集約している。キャンペーン単位で紐付けているので、新しいキャンペーンを作ったら紐付けるだけでよい。

追加するときは `scripts/add_competitor_negatives.py` のリストに足して再実行する（冪等）。Google広告のUI「ツール > 除外キーワードリスト」からも編集できる。

**診療科違い（呼吸器科・消化器科・循環器科・心療内科など）は除外しない方針**（オーナー判断）。

## 4. 効果測定の構成

計測は**HP側と procyon 側の2系統**に分かれている。混同しないこと。

| 知りたいこと | 見る場所 | 状態 |
|---|---|---|
| 広告クリック→LINE追加の意思 | Google Ads「LINE友だち追加」CV | 動作中（2026-08-10に修正） |
| 実際の友だち追加数 | LINE公式アカウントの経路別URL統計 | 動作中 |
| 予約総数 | procyon `reservationCount` | 動作中だが鈍い（後述） |
| 広告経由の友だち追加 | procyon `lineFollowGoogleAdsCount` | **常に0件**（helix#1778 待ち） |

**「ローカルアクション-経路」CVは経路タップであって来院でも予約でもない。** 日によって0〜16件と振れ幅が大きく、判断材料にしない。

**`reservationCount` の正体**は「その日に作成された対面予約の総数」。作成時刻ベースで、キャンセルを含み、流入元でフィルタしていない（自然検索もリピーターも全部入る）。広告の増分を測る指標としては鈍いので、単日の前後比較で効果を判定しない。

### HP側のCV送信の仕組み

- `frontend/src/config/line.ts` にタグIDとCVアクション、通常/広告用の友だち追加URLを定義
- `frontend/src/layouts/Layout.astro` が、`a[href*="lin.ee/"], a[href*="line.me/"]` に該当するリンクを href 基準で全部拾ってクリックCVを発火する。コンポーネント経由か手書きかを問わず拾えるので、今後ボタンを追加しても印を付ける必要はない
- gclid 付き流入時は友だち追加URLを広告用の経路別URLに差し替える。判定結果は sessionStorage に持ち越すので、着地ページ以外でも維持される
- 友だち追加の完了はLINEアプリ内で起きサイトからは観測できないため、**クリック（＝追加の意思）をCVとして数える**設計。実数はLINE公式アカウントの経路別URLの友だち数で答え合わせする

### procyon 側（keiyousya/helix）

`line_users.acquisition_source`（organic/google_ads）に記録して `lineFollowGoogleAdsCount` として返す設計。DBカラム・保存処理・集計クエリ・`procyon-line` の受け口まで実装済みだが、**`?source=` を付けて LIFF を起動する導線が存在せず常に NULL**。

HP側の広告導線が `lin.ee` の経路別URL（LINE公式アカウント側の友だち追加経路）であり、その後 LIFF が開かれるときのURLにクエリが引き継がれないため。詳細と対応案は helix#1778、症状は helix#1745。

## 5. 採算の目安

保険診療は単価を自分で決められないため、ROASより**損益分岐CPA**で見るほうが意思決定に直結する。

損益分岐CPA ＝ 平均診療単価 × 想定来院回数 × 限界粗利率

平均単価5,000円・再診率10%（＝来院1.1回）・限界粗利率80%（院外処方で薬剤費は薬局側、夕方帯はスタッフと家賃が固定費なので追加1人の限界費用は検査試薬程度）と置くと、**損益分岐CPAは約4,400円**。

実測の増分CPAが最悪の日で1,930円なので、**広告費の水準そのものは採算上の問題になっていない**。平日の診療キャパは20人に対し実績11人前後（稼働率56%）で、受け入れ余地もある。

**それでも予算を積むと予約が増えないので、ボトルネックは予算でもキャパでもない。**「半径4km・その時間帯に内科を探している人の絶対数」と「その中で勝てていない広告ランク」が制約になっている。

> ⚠️ 再診率10%を「来院1.1回」と解釈している。**10%の方が長期に通院されるならLTVは跳ね上がり、損益分岐CPAは数万円規模になる**（3回通院で12,000円、慢性疾患で年12回なら40,000円超）。ここの実態確認は分析精度への影響が大きい。

## 6. トラブルシュート

### 新しいキャンペーンを作った直後に単価が暴れる

入札戦略の学習期間を疑う。

```bash
gads report --query "SELECT campaign.id, campaign.primary_status_reasons, campaign.bidding_strategy_system_status FROM campaign"
```

`BIDDING_STRATEGY_LEARNING` / `LEARNING_NEW` が出ていれば学習中。過去CPCの相場を持たない TARGET_SPEND が予算を使い切ろうとして上限CPCまで入札するため、クリック実費が上限に張り付く。

**対処:** 上限CPCを実績CPCの1.5〜2倍程度まで引き下げて上限を締める。学習完了まで1〜2週間はこれ以上構造を変えずに待ち、単日の数字で判断しない。

2026-08-10の実例では、分割直後の平日初日にCPC 137円（前週45〜75円）・CTR 3.9%（前週5〜6%）まで悪化し、14時の時点で日予算の87%を昼枠が消化して本命の夕方が空になりかけた。

### コンバージョン数がおかしい

合計ではなく**アクション別の内訳**を見る。合計だけ見ていると「ローカルアクション-経路」に埋もれて気づけない。

```bash
gads report --query "SELECT segments.conversion_action_name, metrics.conversions, metrics.all_conversions FROM campaign WHERE segments.date DURING LAST_30_DAYS"
```

2026-08-10、この方法で「LINE友だち追加」が40日間0件だったことが判明した。原因は Astro の `define:vars` 付き `<script>` がIIFEで包まれ `function gtag()` がグローバルにならず、`window.gtag` を条件にしていたCV送信が常にスキップされていたこと。

> **教訓: Astro の `define:vars` スクリプトで宣言した関数はグローバルにならない。** グローバルに置きたいものは `window.` へ明示代入する。`gtag('js')` / `gtag('config')` は `window.dataLayer` がグローバルなので動いてしまい、**クリックイベントだけが落ちる**という気づきにくい壊れ方をする。

### procyon の予約数APIが404を返す

パスにクリニックのスラッグが入る形に変わっている（2026-08-10のサーバー移行）。旧パス（スラッグなし）はS3の `<Error><Code>NoSuchKey</Code>` というXMLを返すため、認証エラーやサーバー障害と紛らわしい。**404を見たらまずパスを疑う。** APIキーは移行後も同じものが通る。

### リフレッシュトークンが失効した

`invalid_grant: Token has been expired or revoked` は珍しくない。`python scripts/regen_refresh_token.py` で再取得する（ブラウザ承認が必要なので人が実行する）。承認ページを途中で閉じるとローカルサーバーがポートを掴んだまま残るので、再実行前にプロセスを kill すること。

## 7. 変更手順

| やりたいこと | 手段 |
|---|---|
| 日予算の変更 | `gads budget set --campaign-id <ID> --amount <円>` |
| 上限CPCの変更 | `python scripts/set_cpc_ceiling.py --campaign-id <ID> --cpc <円>` |
| 競合名の除外追加 | `scripts/add_competitor_negatives.py` のリストに追記して再実行 |
| 除外キーワード（個別） | `gads keyword add --ad-group-id <ID> --text "..." --negative` |
| 配信スケジュール・入札調整 | `gads.client` を使う専用スクリプト（CLIは入札調整・既存削除に非対応）|
| 休診期間の配信停止 | `gads campaign end-date --campaign-id <ID> --date YYYY-MM-DD` |

**配信スケジュールを変更するときは、既存の削除と新規作成を単一リクエストにまとめる。** 分けると原子的に適用されず、スケジュールが一瞬消えて終日配信になる事故が起きる。

**広告文に避妊・アフターピル・処方薬関連のワードを入れないこと。** BIRTH_CONTROL 判定で APPROVED_LIMITED になる。避妊・性感染症系の集患はLPのSEOに任せる。なおアフターピルの検索広告は日本では構造的に承認されない。

**RSAはテキストを後から編集できない。** 修正するときは新規作成→旧広告を停止する（`AdGroupAdService` の update で `update_mask=status`）。

## 8. 次にやること

優先度順。上から順に、予算を増やさずに配信量を増やす施策になっている。

1. **コンバージョン計測の実データを貯める** — 2026-08-10にgtagのバグを修正したので、数日分たまったら入札戦略を「クリック数の最大化」から「目標CPA」へ切り替える。損益分岐CPA 4,400円に対し実測が大きく下回っているため、効果が最も大きい変更になる見込み
2. **LPの改善** — 品質スコアのLP項目が全キーワードで「平均以上」に届いていない。夜間診療・土日診療の専用ページ（またはアンカー付きセクション）を作り、キーワード群ごとに送り先を変える
3. **広告グループの意図別分割** — 品質スコア8の語と1の語が同じ広告グループ・同じ広告文になっている。夜間／土日／エリア／一般内科に分け、広告文をそれぞれの意図に合わせる
4. **マッチタイプの見直し** — 1のCV計測が整ってから判断する
5. **昼→夕方への配分シフト** — 昼帯のCTRが3〜4%に対し夕方は9〜17%。ただし昼の「先取り検索」を削る判断になるため、1のデータで裏を取ってから
6. **helix#1778 の対応** — procyon側で広告経由の友だち追加を識別できるようにする
