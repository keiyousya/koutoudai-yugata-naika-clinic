# 点検用UKEファイルの出力と OASCIS 登録

対象月: $ARGUMENTS

OASCIS には請求用ではなく、院外処方の医薬品も含んだ**点検用レセプト**の UKE ファイルを登録する。1か月ごとに「A. 42 明細書で点検用レセプトを作る」→「B. 44 総括表・公費請求書で社保・国保のファイルを出す」を繰り返し、最後に「C. 請求年月を直して匿名化し、OASCIS に登録する」。

出典はアルファシステムのマニュアル「点検用レセプト出力方法 (2).pdf」（`G:\マイドライブ\勾当台夕方内科クリニック\アルファシステム\`）。2026-10-02 に R8.4 分で A・B、2026-10-05 に C を実際に通して手順を確認した。OASCIS 登録の背景は `shisetsu-kijun/gairai-kansen-taisaku-kojo/README.md`。

## 前提

- WebORCA: https://weborca.cloud.orcamo.jp/ 。**ログインはユーザーが手動で行う**（パスワードは入力しない）。新しいタブで開いてログインを頼み、終わったら進める
- ユーザーが別タブで WebORCA を開いていると処理がぶつかるので、閉じてもらう
- 画面の座標はウィンドウの大きさで変わる。**ボタンはラベルで探し、毎回スクリーンショットで位置を確かめてからクリックする**
- 処理中はスクリーンショットがタイムアウトしやすい。数秒 `wait` してから撮り直す
- 日付欄は `R8.5` のように入力して Tab で確定する（表示は `R 8. 5` に整形される）

## 手順（1か月分）

### A. 42 明細書（点検用レセプトの作成）

1. マスターメニュー「01 医事業務」→ 業務メニュー「42 明細書」
2. 右上のプルダウンを **「2 点検用レセプト（院外処方含）」** に切り替える。**初期値は「1 提出用レセプト」なので必ず変える**
3. 「一括作成」・医保「全件」のまま、**診療年月** に対象月を入れる
4. 右下「確定」→ 確認画面に「【点検用レセプト】令和X年X月 入院外分新規作成処理を行います」と出ることを確かめて OK
5. 処理結果を見る
   - 「処理は正常に終了しました」→ F1「戻る」
   - 赤字「主科未設定分又は種別不明分がありますので印刷画面で確認して下さい」→ 下の「種別不明の確認」をしてから F1「戻る」で抜ける
6. 「戻る」で業務メニューへ戻る

#### 種別不明の確認

種別不明のレセプトは UKE ファイルに入らない。対象の患者さんと理由をチャットでユーザーに報告する（**患者登録や保険の修正はユーザーの判断なしに行わない**。請求済みの月なので、直すかどうかはユーザーが決める）。

1. 処理結果で F12「印刷」→ 印刷指示画面（総件数が出る）
2. 左上「全件印刷」を押して **「指定印刷」** に切り替える（全チェックが外れる）
3. 一覧の最下部までスクロールし、**「レセプト種別不明」** だけにチェック（件数欄に件数が出ている）
4. 右下「印刷」→ 確認画面で **F10「プレビュー」** → 処理結果で **F12「プレビュー」**
5. プレビュー選択画面の左に患者番号の一覧、右にレセプトが出る。レセプト上部の赤字コメントが理由（例: 「保険組合せ0001は適用開始日が令和8.6.11となっています」＝受診月に有効な保険組合せがない）。「コメントの入力がありません」で右上の種別欄（本人・家族など）が空欄のこともある（R8.8 で2件。本人家族区分の未設定が疑われる）。患者番号・氏名・理由を控える（報告用。ファイルには書かない）
6. 「戻る」を2回でレセプト作成画面へ戻る

### B. 44 総括表・公費請求書（UKEファイルの出力）

1. 業務メニュー「44 総括表・公費請求書」
2. **診療年月を対象月に書き換える。初期値は直近の請求月（例: R8.9）になっていて、そのままだと別の月が出る**
3. 画面下「レセプト電算システム提供データ・公費CSV提供データ」のプルダウンを **「2 点検用（院外処方含）」** に切り替える（初期値「1 提出用」）。ファイル出力先は「5 クライアント保存」のまま
4. 下段「社保レセ電」→ 確認画面「【点検用】社保分（入院外）のレセプト電算データを作成します」→ **F11「印刷しない」**
5. 処理結果「処理は正常に終了しました　レセプト N件」の件数を控えて F1「戻る」
6. **ブラウザのダウンロード確認ダイアログが開くので、ユーザーに確認と OK を押してもらう**（Claude からは操作できない／しない）。押してもらうまで次へ進まない
   - **Claude のクリックでは保存ダイアログが出ないことがある**（2026-10-07 は1回目だけ出て、2回目以降は出ずにタブが固まった）。Chrome のダウンロード履歴にも載らない（通常のダウンロードではない）。そうなったら、4〜6（「社保レセ電」→ F11 → F1 → OK）は**ユーザーに押してもらう**。Claude は A と、B の診療年月・「2 点検用」の切り替えまでを受け持つ
   - 保存ダイアログは WebORCA のタブが前面にないと見えない。ユーザーに「WebORCA のタブで」と伝える
   - ユーザーに社保・国保を続けて押してもらうときは、`TENKENRC.UKE` が現れるたびに IR の2項目目（1=社保 / 2=国保）で判定してリネームするループを `run_in_background` で回しておくと、ファイル名の衝突を待たずに済む
7. `C:\Users\tamur\Downloads\TENKENRC.UKE` ができたら、検証（下記）してから `YYYY-MM_社保_TENKENRC.UKE` にリネームする。**社保・国保とも同じファイル名で落ちてくるので、次を出す前に必ずリネームする**
8. 「国保レセ電」で 4〜7 を繰り返す（確認画面は「国保・広域分」＝国保と後期高齢者がまとめて1ファイル）。リネームは `YYYY-MM_国保_TENKENRC.UKE`
9. 複数月なら診療年月を書き換えて B を繰り返す前に、その月の A を先に済ませる。**複数月は A・B を全月分まとめて済ませてから、C（匿名化・OASCIS 登録）を一括で行う**（匿名化ツールは複数ファイルをまとめてドロップでき、OASCIS も複数ファイルを1回で登録できる）
10. 42・44 のプルダウン（「2 点検用」）は画面を開き直すたびに「1 提出用」に戻る。毎回切り替える
11. 当月請求分（例: 10月上旬の R8.9 分）はレセプトを提出し終えてから出す（点検用は出力時点の内容になるため）

### ファイルの検証

```bash
f=/c/Users/tamur/Downloads/TENKENRC.UKE
iconv -f CP932 -t UTF-8 "$f" | head -1                                   # IR,1,... = 社保（支払基金）/ IR,2,... = 国保連
iconv -f CP932 -t UTF-8 "$f" | grep '^RE' | cut -d, -f4 | sort | uniq -c  # 全件が対象の診療年月（例: 202605）
```

- RE の件数が B-5 で控えた件数と一致すること
- 社保 + 国保 の件数 ＝ A の総件数 − 自費 − 種別不明 になっていること
- IR の請求年月は ORCA で出力した月（202610 など）になっている。OASCIS では**診療年月の翌月**でないといけないので C-1 で直す

### C. 請求年月の修正・匿名化・OASCIS 登録

作業フォルダは `C:\Users\tamur\Downloads\oascis\`。Claude Code に `/add-dir` で追加されていないと Chrome からファイルを添付できない。未追加ならユーザーに `/add-dir C:\Users\tamur\Downloads\oascis` を頼む。

1. **請求年月を診療年月の翌月に直す**（IR レコードの8項目目だけ）。**`sed -b` で CRLF を保つ**（`-b` なしだと改行が LF になって壊れる）

   ```bash
   M=2026-05; NEXT=202606   # 診療年月 / その翌月
   cd /c/Users/tamur/Downloads/oascis && mkdir -p work/$M/社保 work/$M/国保
   for k in 社保 国保; do
     sed -b -E "1s/^(IR,([^,]*,){6})[0-9]{6},/\1$NEXT,/" "../${M}_${k}_TENKENRC.UKE" > "work/$M/$k/RECEIPTC.UKE"
     cmp -l "../${M}_${k}_TENKENRC.UKE" "work/$M/$k/RECEIPTC.UKE" | wc -l   # 数バイトだけ変わり、サイズは同じ
   done
   ```

2. **レセプト匿名化ツールで匿名化する**（ここだけ**ユーザーの画面操作が必要**）
   - ツール: `Downloads\oascis\tool\ReceiptMask_1.4.1\ReceiptMask.exe`（JIHS の署名付き）。無ければ https://oascis.jihs.go.jp/manual/anonymize-tool の zip を取って展開する。zip 内のフォルダ名が文字化けするので、展開後にリネームする
   - **CLI 引数は受け付けない**（ファイルを渡して起動しても読み込まない）。ボタンも UI Automation から押せない。Claude は `Start-Process` でツールを起動し、`explorer.exe` で `work\YYYY-MM` を開くところまでやる
   - ユーザーに頼むこと: 「ファイル名に年月を付加して単一フォルダーに出力［推奨］」にチェック、「UKEファイルの請求年月を指定」はチェックしない、`社保\RECEIPTC.UKE` と `国保\RECEIPTC.UKE` をウィンドウにドロップ、確認に OK。**警告（703=請求年月の誤り、704=医薬品が少ない＝院外処方の抜け）が出たら、OK を押す前に内容を聞く**
   - 結果は `tool\ReceiptMask_1.4.1\log.txt` で確認できる。出力は `tool\ReceiptMask_1.4.1\5119874\RECEIPTC_<請求年月>_01.UKE`（社保）と `_02.UKE`（国保）
   - 検証: RE の5項目目（氏名）が64桁のハッシュ、HO が 0 埋め、RE の件数が B と一致すること

3. **OASCIS に登録する**（https://oascis.jihs.go.jp/ 。右上「ログイン」から**ユーザーが手動でログイン**）
   - トップの「データ登録」欄の file input を `find` で探し、`file_upload` で匿名化済みの2ファイルを渡す（選んだ時点でアップロードが始まる）
   - 「UKEファイル登録確認」で 請求年月（診療年月）・社保/国保・新規/上書き を確認し、**ユーザーの OK をもらってから「登録内容を確定」**
   - 「UKEファイル登録完了」→「データ登録状況を確認する」。対象月の社保・国保が ⌛（取込処理中）→ ✓（取込完了）になる。⚠ や ✕ が出たら、アイコンのメッセージを読んで報告する

## 報告

月ごとに表でまとめる: ファイル名 / 区分（IR） / レセプト件数 / 種別不明の患者番号・氏名・理由 / OASCIS の登録状況。
