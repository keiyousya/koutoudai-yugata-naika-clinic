## キャンペーン構成（2026-08-09に平日/土日で分割）

| キャンペーン | ID | 配信曜日 | 日予算 |
|---|---|---|---|
| 検索_内科_土日 | <WEEKEND_CAMPAIGN_ID> | 土・日 | 3,000円 / 上限CPC 200円 |
| 検索_内科_平日（月水木金） | <WEEKDAY_CAMPAIGN_ID> | 月水木金 | 2,200円 / **上限CPC 100円**（2026-08-10に200→100へ引き下げ） |

平日側の ad_group は <WEEKDAY_AD_GROUP_ID>、RSA は ad_id <WEEKDAY_AD_ID>。両方とも **TARGET_SPEND（クリック数の最大化）**、検索＋検索パートナー＋ディスプレイ拡張ON、半径4km（38.267511, 140.868655）、日本語、除外オーディエンス1件。命名規則は `検索_<商材>_<配信ターゲット>`。専用予算の名前はキャンペーン名に自動追従する（API側からの予算リネームは通らない）。

上限CPCの変更は `gads` に該当コマンドがないので `scripts/set_cpc_ceiling.py`（`target_spend.cpc_bid_ceiling_micros` を FieldMask 指定で更新）を使う。

**分割時の設定引き継ぎは2026-08-10に全項目照合済みで漏れなし** — 入札戦略・上限CPC・キーワード34件・除外キーワード（広告グループ9件＋キャンペーン3件「訪問 診療」「jcho」「jcho 仙台 病院」）・除外KWリスト（両方とも未使用）・半径と座標・地域タイプ（所在地）・ネットワーク・除外オーディエンス・RSAテキスト（見出し13/説明4が旧 <WEEKEND_AD_ID> と完全一致）まで一致。言語だけは新（平日）側にのみ日本語指定があり、旧側は未指定。

**分割した理由:** Google広告に曜日別の日予算という設定は存在しない（「予算スケジュール」は特定の日付範囲用で曜日の繰り返し指定は不可、入札調整では予算上限を動かせない）。分割が唯一の手段。**既存キャンペーンを土日側に残した**のは、平日のほうが週5日ぶんデータが溜まり履歴の回復が速いため。切り替えは日曜に実施＝どちらの操作も当日の配信に影響しない。

**配信スケジュール:**
- 平日: 12:00-13:00(×1.20) / 13:00-14:00 / 16:00-17:00 / 17:00-18:00(×1.25) / 18:00-20:30
- 土日: 12:00-17:00 / 17:00-20:30（両方とも等倍）。土曜だけ枠が2本に分かれているのは調整を試した名残で、配信上は1本と同じ

**✅ 入札調整（ad_schedule の bid_modifier）は TARGET_SPEND でも効く（2026-08-10に決着）。** 8/10の12時台（×1.20）のクリック実費が **240円 = 上限CPC 200円 × 1.20 ちょうど**で、13時台（等倍）は195〜200円で頭打ちだった。上限CPCに乗算される形で確実に適用されている。以前「効かない」と疑ったのは 8/8 の土曜+30%実験でクリック増を確認できなかったためだが、あれは入札が上限に張り付いていない状況だったための見え方で、無効の証拠ではなかった。

## ⚠️ 分割直後の学習期間で単価が暴騰した件（2026-08-10、平日キャンペーン初日）

分割後はじめての平日配信で **CPC 137円**（前週平日は45〜75円）・**CTR 3.9%**（前週5.2〜6.6%）。14時の時点で日予算2,200円のうち1,911円を昼枠が食い尽くし、本命の17-21時が空になりかけた。

**原因は設定漏れではなく入札戦略の学習期間。** `campaign.primary_status_reasons` に `BIDDING_STRATEGY_LEARNING`、`campaign.bidding_strategy_system_status` が `LEARNING_NEW`（旧キャンペーンは `ENABLED`）。過去CPCの相場を持たない TARGET_SPEND が予算消化のため上限CPCまで入札し、クリック実費が195〜240円＝上限に張り付いた。「内科 病院」は絶対上位表示シェア39%（8/3は13%）で最上部を買い漁っていた。

**診断に使ったフィールド:** `campaign.primary_status_reasons` / `campaign.bidding_strategy_system_status` / `metrics.absolute_top_impression_percentage` / `search_term_view` のクリック実費。**新キャンペーン作成後に成績が荒れたらまずこの2つのステータスを見る。**

**対応:** 上限CPCを200→100円へ引き下げ（実績CPC45〜75円なので余裕はある）＋その日だけ日予算を2,200→3,300→**6,000円**へ増額して夕方枠を確保（オーナー判断）。

**🚨 日予算は8/12(水)の配信開始(12:00)前に2,200円へ戻すこと。** 8/11は火曜で休診＋スケジュール外なので配信されず、戻し忘れても8/11中は無害。**戻し忘れると平日4日×6,000円＝週24,000円**で、7月ひと月の総額26,461円をほぼ1週間で使う。

```bash
cd google-ads && .venv/bin/gads budget set --campaign-id <WEEKDAY_CAMPAIGN_ID> --amount 2200
```

学習完了まで1〜2週間はこれ以上構造を変えずに待つ。単日の数字で判断しない。

**増額の期待値（過去実績）:** 平日16-20時に消化できたのは1晩374〜1,354円・表示98〜422回だけ。**夕方枠は在庫が薄く、日予算を積んでも使い切れない。** 増額は「使い切る」効果ではなく「上限CPCに張り付いて夕方の枠を取りに行く」効果として働くので、上限CPCとセットでないと単価が暴れる。

## 分析でわかっていること（2026-06〜08、procyon実予約と突合）

- **土日は平日より効率が良い。** CPC 土54/日59 vs 平日77円、CTR 8.5/8.4% vs 5.7%
- **土12時が最悪の枠。** 広告費シェア15.4%に対し予約シェア1.6%（比率0.10）。診療開始2時間前
- **日曜は12-16時が弱く16時以降が強い。** 12-16時で広告費の68%を使って予約シェアは4割。17-19時の比率は1.5〜2.1
- **朝(9-11時)は広告なしでも予約が発生**（土1.40件/日、日1.25件/日＝全体の9〜12%）。12時ですら成績が悪いため10-11時への前倒しは見送り（2026-08-09判断、12:00開始のまま継続）
- **予算増額の効果は確認できていない。** 8/8は日予算3,000円で3,415円着地・クリック+82%（8/1比）だったが、予約は19件で8/1と同数
- **⭐平日のボトルネックは予算でも配信範囲でもなく「広告ランク」。** 8月の平日の表示シェアは一貫して約10%で、失った理由の内訳は 8/3 ランク90%・予算0%、8/6 ランク90%・予算1%、8/7 ランク77%・予算14%。**半径4km圏内にすでに9割の表示機会が余っている**ので、配信半径を広げても勝てない入札が増えて予算が遠方に薄く散るだけ。ボリュームを増やすレバーは入札とランクしかない。土日は逆に予算不足が主因（8/1 78%・8/2 70%・8/8 63%）

- **平日は1日の予約の半分以上が16時以降に作られる**（8/3は9件中4件、8/5は13件中9件、8/6は13件中7件、8/7は10件中5件が16時以降）。**日中に「今日は予約が少ない」と感じても、その時点ではまだ半分も終わっていない。** 途中経過で慌てて判断しないこと。比べるなら「16時までの累計」を前週の同条件と並べる（平日の16時まで累計は4〜6件が平常値）

**成績の読み方:** Google側のCVは「ローカルアクション-経路」＝経路タップで、実予約とは別物。日によって0〜16件と振れ幅が大きく当てにならない。判断は procyon の実予約で行う（[[procyon-ad-metrics-api]]）。ただし実予約もキャンセル込み・全流入込みの総数なので、広告の増分を測る指標としては鈍い。

**運用インサイト（オーナー談）:** 平日は診療が17-21時なのに12-14時台のCVが多い。社会人が昼休憩に探して夜の受診を予約する「先取り検索」。昼帯の配信は削らない。

**RSA:** 土日は ad_id <WEEKEND_AD_ID>、平日は <WEEKDAY_AD_ID>（テキストは同一・見出し13/説明4）。両方とも審査は APPROVED_LIMITED（BIRTH_CONTROL 由来、分割前からの既知状態）。**広告文に避妊・アフターピル・処方薬関連ワードを入れないこと**（BIRTH_CONTROL でAPPROVED_LIMITEDになる）。避妊/性病系の集患はLPのSEOに任せる。RSAはテキストを後から編集できないので修正時は新規作成→旧停止。ad単位の停止は `AdGroupAdService` の update(update_mask=status) で行う。

**How to apply:** 配信時間/入札の変更はCLI `gads campaign schedule` が入札調整・既存削除に非対応のため、`gads.client` を使う専用スクリプト（remove既存→create新規、bid_modifier指定）で行う。削除と作成は単一リクエストにまとめると原子的に適用され、スケジュールが一瞬消えて終日配信になる事故を防げる。キャンペーン新規作成時は `contains_eu_political_advertising` が必須。除外キーワードは `gads keyword add --negative`。アフターピル広告は不可（[[afterpill-google-ads-not-approvable]]）。
